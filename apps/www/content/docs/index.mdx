Otterdeploy is a self-hostable deployment platform. You bring a supported Linux
host, or a cluster of them, and it gives you git-sourced builds, managed
databases, a Caddy edge with automatic HTTPS, opt-in pull request previews, live logs,
metrics and scheduled backups. The control plane and workloads run on your
hardware; no hosted Otterdeploy service sits in the request path.

<Callout type="warn" title="Under active development">
  Interfaces and schemas still change without migration paths. Run it on
  something you'd be willing to rebuild, and read
  [what isn't built yet](/docs/start/concepts#what-isnt-built-yet) before you
  plan around a feature.
</Callout>

## What you can run

- **Services**: apps built from a git repo (framework auto-detected, or your
  own Dockerfile), from a pre-built image, or from an upload.
- **Databases**: PostgreSQL, Redis, MariaDB, MongoDB and ClickHouse,
  provisioned as first-class resources next to the services that use them.
- **Compose stacks**: a whole `docker-compose` project as one resource, pasted
  inline or pulled from a repo.

Core workflows are available through the dashboard and the `otterdeploy` CLI.
Both use the same typed API.
