A database is a first-class resource, not a container you wire up yourself. It
gets provisioned next to the services that use it, and those services reference
it by name.

## Engines

| Engine | Value |
| --- | --- |
| PostgreSQL | `postgres` |
| Redis | `redis` |
| MariaDB | `mariadb` |
| MongoDB | `mongodb` |
| ClickHouse | `clickhouse` |

```bash
otterdeploy add database postgres --engine postgres
```

<Callout title="Other data services are templates">
  RabbitMQ, MinIO, Meilisearch and similar are available as
  [compose stack templates](#templates), not as managed database engines. The
  five above are the whole `database_engine` enum.
</Callout>

Provisioning reports live progress (image pull, then provision) rather than a
spinner that resolves into either "ready" or nothing.

## Connecting a service

Don't paste a connection string. Reference the database and let the resolver
fill it in at deploy time:

```json
{
  "env": {
    "DATABASE_URL": "${{postgres.DATABASE_URL}}"
  }
}
```

Individual PostgreSQL exports are addressable too, so you can compose a string
yourself when a library insists:

```json
{
  "DSN": "postgres://${{primary.PGUSER}}:${{primary.PGPASSWORD}}@${{primary.PGHOST}}:${{primary.PGPORT}}/${{primary.PGDATABASE}}"
}
```

Because the lookup is by **name** at deploy time, the same manifest resolves to
a preview's own database copy when it runs in a preview. See
[environment variables](/docs/guides/environment#references) and
[previews](/docs/guides/previews).

## Reaching it from outside

By default a database is only reachable inside the cluster. A standalone
PostgreSQL database can be exposed at layer 4 for a laptop or external tool:
the same Caddy edge routes raw TCP to it. Other database engines and databases
hosted on a shared server do not support public exposure.

Use this deliberately. An exposed database is on the public internet, protected
by its credentials and whatever the [firewall](/docs/start/install#security-defaults)
blocks.

## Ephemeral credentials

Short-lived roles can be issued for a PostgreSQL database instead of handing
out the main credentials. They expire on their own: Postgres's `VALID UNTIL` stops new
logins at expiry, and a sweeper runs every minute to terminate live sessions
and drop the role behind them.

## Backups

PostgreSQL, MariaDB and MongoDB can be backed up by encrypted logical dump on a
schedule you set. Back up the data volume for Redis or ClickHouse. See
[backups](/docs/guides/backups).

## Browsing the data

Each database resource has a **Data** tab. You don't need to expose it or
reach for a separate client to look inside.

| Engine | What you get |
| --- | --- |
| PostgreSQL | Table list with row estimates, a SQL console, and an editable row grid |
| MariaDB | Tables and rows |
| MongoDB | Collections and documents |
| Redis | Keyspace, keys and values |
| ClickHouse | Not covered by the browser |

Queries run inside the database's own container, so nothing is exposed to the
network to make this work.

### Reads and writes are separate permissions

- **`database: read`**, list tables, collections, keys.
- **`database: query`**, run a SQL query. Postgres runs it in a **read-only
  session** (`default_transaction_read_only=on`), so a write in the console
  errors at the server rather than relying on the UI to stop you.
- **`database: write`**, `execute` for arbitrary statements, and `mutateRow`
  for grid edits, which builds its statement from structured input rather than
  passing your text through.

Every write records who ran what: `execute` puts the statement on the
request's wide event, so the [audit log](/docs/guides/servers#audit) captures
the actual SQL.

## Templates

RabbitMQ, MinIO, Meilisearch and other data services ship as Compose templates,
not as managed database resources. See [App templates](/docs/guides/templates)
for the catalog, its verification checks and the staged deployment flow.
